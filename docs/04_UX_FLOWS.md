# 04. UX 흐름

> 처음 흐름도 이미지: `canonical_user_flow_ui_svgs/PREVIEWS/canonical_user_flow.jpg`. 화면 모양은 **리디자인 v2 확정 시안**(2026-11-21, 07 D64, 05 맨 앞 표)이 기준이다.
> 아래는 그 흐름도 + 확정된 변경(공유 진입, 이메일 틀, 코스 루프, 아이디 가입, 취향은 저장한 장소 기준)을 반영한 것이다. 기준일 2026-11-21.

## 0. 전체 지도

```
[앱 시작]
   ├─ 미로그인 → A. 인증
   └─ 로그인 → 홈 ─┬─ 코스 탭   → D. 코스 만들기 / 관리
                   ├─ 저장됨 탭 → C. 저장 라이브러리 → 장소 상세
                   ├─ 장소 추가 탭 → B. 추출 (링크 입력 폴백)
                   └─ 마이 탭   → F. 내 취향 · 설정

[외부] 인스타그램 릴스 → 공유 → 우리 앱 ──→ B. 추출 (주 경로)
[외부] 초대 링크 ───────────────────────→ E. 파티 초대 수락
```

**홈에서 가는 곳 (2026-10-20, 05 #9)**: 코스 카드(③④) → 코스 상세 · `n개 더 보기` → 코스 탭 · 새 저장 제안(②) → 코스 만들기(새로 저장한 곳 미리 선택) · `장소 저장` → 장소 추가 탭 · `코스 만들기` → 위저드 1단계 · **지역별로 시작하기**의 지역 줄 → 저장됨, `코스 만들기` → 위저드 1단계(3단계가 그 지역 필터로 열림, 07 D52) · 사진 타일 → 장소 상세 · 최근 저장 `모두 보기` → 저장됨 탭

하단 탭 5개(홈·저장됨·코스·장소 추가·마이)는 다섯 칸 같은 크기(가운데 띄운 버튼 없음, v2 07 D64)이고 **현재 라우트 기준**으로 활성 표시(잉크 + 굵은 선). 탭바가 숨겨지는 화면: 인증 전체, 보관함 선택 시트, 새 보관함 모달, 코스 만들기 위저드 및 장소 선택/추가, 초대 수락, 지도 풀스크린.

## A. 인증

```
로그인 (#1: 아이디 · 비밀번호 + 간편 로그인 카카오 · Google)
    ├─ 아이디 로그인 ─ 성공 → 홈 / 틀림 → 두 칸 빨간 테두리 + 한 줄 오류
    ├─ 회원가입 → 약관 동의 (1/2) → 계정 정보 (#2-1, 2/2) ─ 이미 있는 아이디 → 칸 아래 오류
    │                                              └ 성공 → 가입 완료 → 홈
    ├─ 간편 로그인 ─(신규)→ 약관 동의 → 프로필 설정(닉네임만) → 가입 완료 → 홈
    │             └(기존)→ 홈
    ├─ 계정 충돌 (#5)  → 기존 계정과 연결 / 다른 계정
    ├─ 소셜 로그인 창에서 취소 → 로그인 화면 그대로 + 스낵바 (D35)
    ├─ 소셜 인증 오류 (#6, 실패만) → 다시 로그인 / 고객센터
    └─ [flag] 이메일로 로그인 (#7) ─ 실패 → 인라인 오류 (#8)
                                  └ 비밀번호 찾기 / 이메일 가입 (TODO 스텁)
```
- 취향은 가입 중에 고르지 않는다(저장한 장소로 계산, 07 D54 · D64).
- 이메일 진입 링크는 **feature flag가 켜졌을 때만** 로그인 화면에 노출.
- 이메일 로그인은 틀만: 폼 검증(형식/빈 값), 오류 표시, 로딩 상태까지.
- 공유로 들어왔는데 로그인 전이면 **URL 보류 후 로그인 완료 시 재개** (02 문서 §5.3).

## B. 장소 추출 · 저장 (핵심)

### 주 경로 — 인스타 릴스 "공유"
```
릴스 → 공유 → (시스템 공유 시트) → 우리 앱
   → URL 검증 → [추출 진행 중] → 추출 결과 검토 (#11) → 보관함 선택 (#12) → 저장 완료
                                    └ 실패/없음/비공개 → 오류 상태 → 재시도 or 링크 직접 입력
```
- 링크 입력 화면(#10)을 **거치지 않고** 결과 검토로 바로 진입하며 분석은 자동 시작.
- 추출 진행/오류 상태는 디자인에 없음 → 임시 컴포넌트로 구현 후 필요 시 디자인 요청.

### 보조 경로 — 앱 안에서 링크 입력
```
장소 추가 탭 (#10) → 맨 위 링크 칸에 붙여넣기 → 찾기 → (이후 동일)
```
- 장소 추가 탭은 링크 칸이 맨 위, 그 아래 지도에서 찾기 · 릴스 공유 3칸 안내(주 경로라는 설명), 맨 아래 최근 추가한 장소(v2 07 D64 — D55의 순서를 바꿈).
- SNS 주소를 이미 알고 있을 때 사용. 링크 줄은 찾는 중 · 결과 · 실패 화면에서도 같은 자리 · 같은 모양(07 D26).

### 결과 검토(#11) 규칙
- 장소 행 체크(복수), **이미 저장됨**은 흐리게 · 선택 불가
- 링크 줄의 `게시물 보기`로 출처 확인
- 행의 `보관함` → 그 장소의 보관함 시트(`n곳 모두 적용` 가능) → 확인 → 목록에 보관함 이름. 고르지 않은 곳은 보관함 없이 저장.
- CTA: `N곳 저장` 한 번으로 저장
- 저장 뒤: 결과 화면에 남고 스낵바 `n곳을 저장했어요 · 보기` → 1곳은 장소 상세, 여러 곳은 저장됨(한 보관함이면 그 보관함). 남은 곳을 이어서 저장하거나 `완료` (07 D26)

## C. 저장 라이브러리

```
저장됨 [전체 | 보관함 | AI 추천]
  ├ 전체 → 저장 지도(#18) ┐
  ├ AI 추천 → 저장 지도(추천받은 곳만)
  └ 보관함 → 새 보관함(#15) / 빈 보관함(#16) / 보관함 상세(#17) → 보관함 지도(#19) ┤
                                                                         └→ 장소 상세 (#20)
장소 상세 ─ 저장됨 버튼 · 담은 보관함 `변경` (#12 시트) / 하단 `이 장소로 코스 만들기` (장소 사전 선택)
빈 보관함 ─ 저장한 장소에서 추가 / 링크로 장소 찾기 (→ B)
```
- 상단바 `지도`는 **현재 탭 맥락**으로 바로 지도 진입 (카테고리 탭은 걸린 카테고리 그대로, 중간 선택 화면 없음). (2026-10-20, 떠 있는 버튼 제거)
- 전체 탭: 보기 방식 칩(`지역별` 기본 · `업종별` · `최근 저장한 순` · `이름순`) → 지역별이면 `필터`가 지역, 업종별이면 업종(여러 개). 고른 값만 칩으로, ×로 하나씩 푼다. 보기 방식을 바꾸면 필터를 모두 푼다. 묶음이 6곳을 넘으면 세 곳 + `모두 보기`(07 D53).
- 저장 지도: 지도 화면엔 얇은 시트(가로 카드 한 줄) + 지도 위 `목록 n`, 직접 저장/추천받은 곳 · 자동 검색은 `필터` 시트 안. 보관함 탭은 2열 표지 그리드(`저장한 장소 전체` 줄 없음, v2).
- 한 장소는 여러 보관함에 속할 수 있다.

## D. 코스 만들기 — 루프 포함

```
코스 목록/빈 상태 ──(+ / 첫 코스 만들기)──┐
 장소 상세 `코스 만들기` ──────────────────┤  (해당 장소 사전 선택)
 보관함 상세 `이 보관함으로 코스 만들기` ──┘  (보관함 장소 일괄 불러오기)
                    ▼
 [1/4 정보]  이름 · 날짜 칩(2주 + 달력) · 출발 시간   (분위기 칩 없음 v2, 장소는 3/4에서만, 뒤로 나갈 때 확인 없음)
                    ▼
 [2/4 동행]  혼자 가요 / 함께 가요 두 칸
        ├ 혼자 : 나의 취향으로 추천
        └ 함께 : 내 파티 고르기(목록) 또는 새 파티(파티원 행 + 초대하기, 시트 27) — 초대 수락을 기다리지 않고 다음으로 진행
                    ▼
 [3/4 장소]  지도 위에서 저장한 장소 고르기 (체크, 순서 번호 없음 — 순서는 AI가 정함)
             카드 · 목록은 지금 지도 영역 안만 · `목록` → 올라오는 시트(끌어내리면 지도)
             → 「n곳으로 코스 추천받기」 (추천 지역 = 고른 곳이 가장 많은 지역, 07 D51)
                    ▼
 [4/4 AI 추천]  결과 = 코스 상세와 같은 화면  ◀──────────┐
        ├ 장소 누르기 → 바꾸기 · 이번만 빼기 · 앞으로 추천하지 않기
        ├ 「편집」 → 빼기(X) · 순서 · 장소 추가 ──────────┤
        ├ 「다시 추천」 = AI 자리만 다시 채움 (되돌리기) ──┘  (반복 가능)
        └ 「코스 저장」
                    ▼
 [코스 상세 32] (완료 화면 없음, 제목 위 "코스가 저장되었어요")
        └ 「편집」 → [코스 편집 32-1] 빼기 · 순서 · 장소 추가 · 다시 추천 → 「저장」
```

### 장소 빼기 (07 D24)
| 누가 넣은 장소 | 동작 | 범위 |
|---|---|---|
| AI 추천 | 다른 곳으로 바꾸기 · 이 코스에서 빼기 · 편집 X | **이번만**: 이 코스를 다시 추천할 때도 안 나옴, 다른 코스에는 나올 수 있음 |
| AI 추천 | 앞으로 추천하지 않기 (시트에서만, 빨간 글자) | **차단**: 모든 코스 추천에서 안 나옴(파티 코스는 파티원 누구의 차단이든 빠진다 — 서버 규칙, 07 §3), 마이 → 추천하지 않는 장소에서 해제 |
| 내가 고른 장소 | 이 코스에서 빼기 · 편집 X | 이 코스에서만 빠짐, 저장됨에는 그대로 (차단 없음) |

- 모든 빼기·다시 추천에는 스낵바 `되돌리기`. 되돌릴 수 있으니 확인 창은 띄우지 않는다.
- 편집 X는 항상 이번만(가벼운 버튼에 차단을 걸지 않는다).

### 루프 규칙 (확정: "장소 수정 → AI 재추천"은 반복 가능)
1. 루프는 **4/4 단계 안에서 반복**된다. 진행 바는 4/4로 유지, 새 단계를 만들지 않는다.
2. 사용자가 고른 장소(`USER`)와 AI가 넣은 장소(`AI`)를 **항상 시각적으로 구분**한다 (주황 번호 원 + 작은 ✦ + `AI 추천` 태그, 07 D62). 추천 이유는 장소를 눌러 뜨는 시트에서 처음부터 펼쳐 보여 준다(07 D40 → D64).
3. 수정 후 "다른 추천"을 누르면 **현재 코스 상태를 기준으로** 다시 추천받는다. 사용자가 방금 뺀/바꾼 추천은 다시 나오지 않아야 자연스럽다 → 서버 지원 여부 확인(06 문서).
4. 재추천 중에는 이전 결과를 유지한 채 로딩 표시(깜빡임/빈 화면 방지). 실패하면 이전 결과로 복구 + 재시도. 기다리는 동안 언제든 취소할 수 있다 — 처음 추천은 3/4로, 다시 추천·바꾸기는 그 동작 전으로 돌아간다(07 D33).
5. 4/4에서 뒤로 가면 3/4(장소)로 가고 **입력은 유지**. 3/4에서 장소가 바뀌면 이전 AI 결과는 무효 안내.
6. 저장 후(#32)에는 `편집`(#32-1)에서 같은 동작(빼기·순서·장소 추가·다시 추천)을 하고 `저장`해야 반영된다. 바꾼 채로 닫으면 확인. **서버 모드 주의**: 팀 서버가 확정한 코스의 수정 · 다시 추천을 409로 막아 지금은 저장한 코스에서 `편집`이 숨겨져 있다(Mock은 보임). 파티원끼리 저장한 코스를 계속 고치는 것이 핵심이라 서버 수정을 요청 중이다(07 §3, 06 §7).
7. 재추천 횟수 제한이 있다면(비용/쿼터) 서버 응답에 따라 안내.
8. 다시 추천은 **내가 고른 장소를 두고 AI 자리만** 바꾼다(07 D24). 고정할 장소를 직접 고르는 기능은 나중에 추가.

### 파티 코스 (함께 갈게요)
```
2/4 함께 → 새 파티 → 초대하기 → 초대 시트(카카오톡 / 링크 복사) → 3/4 장소 고르기(내 장소만)
   → 파티원이 링크 열기 → [초대 수락 28] → 코스 참여 (내 저장 장소·취향 반영 스위치)
   → 파티원 취향 종합(서버) → 4/4 AI 추천 (취향 반영 비율은 표시하지 않고, 일정 카드 안 장소 목록 위에 한 줄 "파티원 n명의 … 취향을 반영했어요" + `누구 취향인지 보기` → 장소마다 누구 취향인지 시트 — 07 D46 · D57)

2/4 함께 → 전에 만든 파티 고르기(이미 멤버라 초대 없음) → 3/4 내 장소 → 4/4 → 저장
   → 상세에서 「민지, 랑이에게 알릴까요?」 → 코스 링크 보내기 → 파티원이 링크 열기 → 코스 상세 → 편집에서 자기 장소 넣기
```
- 기존 파티는 초안을 **내가 만들고 저장 후 알리는** 흐름이다. 저장 전 코스는 파티원에게 보이지 않는다. 링크를 안 받아도 파티원 앱의 홈 · 코스 탭(모임/파티 코스)에 보인다(07 D34).
- 추가 가능: 실시간 함께 편집, 앱 푸시 알림(NEEDS BACKEND).
- 초대 수락 화면에는 **참여 시 공개되는 정보**(취향 키워드, 코스에 선택한 장소)를 명시.
- 코스가 만들어진 뒤에는 **초대된 파티원도 코스 상세 편집에서 장소를 추가·삭제·순서 변경**할 수 있다(07 D23). 동시 수정은 서버가 코스 `revision`으로 막는다(먼저 저장한 사람이 이기고 나중 사람은 409 "새로 불러와 주세요"). 초대 링크는 파티장만 만들 수 있다(07 D43).
- 초대 상태 예외(만료·이미 참여·인원 초과)는 디자인에 없음 → 간단한 에러 상태로 처리.

## E. 파티 초대 수락 (파티원 관점)

```
초대 링크 → (미로그인이면 인증 후 복귀) → 초대 수락 (#28)
   ├ 코스에 참여하기 → 코스 목록의 "모임/파티 코스" 탭에 표시
   └ 참여하지 않기
```
- 미로그인 상태에서 링크를 열면 초대 토큰을 보류했다가 인증 후 복귀(공유 URL 보류와 같은 패턴).
- 취향은 저장한 장소로 계산하므로 참여 후 따로 고르게 하지 않는다(07 D54).

## F. 내 취향 · 마이 (v2, 07 D54 · D64)

```
마이 (#33) ─ 숫자 세 칸 → 저장됨 / 코스(내 코스) / 코스(함께하는 코스)
          ├ 내 취향 `보기` → 내 취향 (#34): 저장한 곳 업종 다섯 · 추천하지 않는 장소 · 「장소 더 저장하기」 → 장소 추가
          ├ 추천하지 않는 장소 (#32-2) → 해제 (스낵바)
          ├ 알림 · 개인정보 설정 · 도움말 및 문의 (준비 중)
          └ 로그아웃 → 확인 → 로그인
코스 만들기 2/4 혼자 → `취향 보기` → 내 취향 (#34)
```
- 취향은 **직접 고르지 않고 저장한 장소로 읽는다**(팀 서버가 저장한 장소로 취향을 계산). 마이 요약 줄에 많이 저장한 업종 셋을 보여 준다(서버 요약 값).
- 직접 고르는 칩 화면(예전 #34 취향 설정)은 `FeatureFlags.manualTasteEnabled`(기본 false)로 Mock에서도 꺼 둔다. 서버가 직접 고르는 취향을 지원하면 켜고, 그때는 마이 `수정` → 칩 선택 → `취향 저장하기` → 마이 복귀 + 스낵바. 칩 그룹/항목은 서버 키워드 체계를 따른다.
