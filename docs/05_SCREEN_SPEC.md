- 상태: 버튼 로딩, 플랫폼 제한(Apple은 iOS 정책상 소셜 제공 시 필수 — 심사 요건 확인)

- UI: 제목 `로그인할 수 없어요` + 오류 설명, `SectionCard` `이렇게 해 보세요`(구분선 행 2개), `다시 로그인하기` / `고객센터 문의`. 뒤로(왼쪽 위)도 둔다. 계정 연결(#5)과 같은 틀 (07 D37)
- SDK · 서버 **실패일 때만** 온다. 사용자가 취소하면 로그인 화면에 남고 스낵바만 띄운다 (07 D35)

- **틀만 구현**: 폼 검증(이메일 형식/빈 값), 버튼 활성/로딩, 오류 표시. 실제 인증은 stub/Mock. `비밀번호 찾기`, `이메일로 가입하기`는 TODO 라우트.
- flag off 시 진입 불가.

### 8★ 이메일 로그인 오류 · 7의 상태  — `ui_additions/01_AUTH/08_email_login_error.svg`

## 2. HOME

### 9 홈 · `/home`  (2026-10-20 개편, 07 D20)
- 헤더: 제목 "홈" + 알림 버튼 (부제 없음, D16)
- **맨 위 자리 하나만 상황에 따라 바뀐다** (`resolveHomeTop`, 코스는 당일 일정 기준)
  | 상황 | 조건 | 맨 위 |
  |---|---|---|
  | ① 처음 | 저장 0곳 · 예정 코스 없음 | 시작 안내(릴스 ⋯ → 공유 → APT 3단계 + `링크 붙여넣기`) |
  | ② 저장만 | 예정 코스 없음 | 새로 저장한 곳이 있을 때만 한 줄 제안 "최근 n곳을 저장했어요 / 코스로 만들어 볼까요? ›" + 사진 최대 3장. 누르면 그 장소들을 미리 고른 채 코스 만들기, X(44×44)로 닫기 → 스낵바 `되돌리기` |
  | ③ 다가오는 코스 | 오늘 이후 날짜 코스 있음 | 가장 가까운 코스 카드: D-day(크게) · 이름 · `10월 21일 (수) · 4곳` · 대표 사진 1장. 2개 이상이면 `다가오는 코스 n개 더 보기 ›` → 코스 탭 |
  | ④ 오늘 출발 | 코스 날짜가 오늘 | 같은 카드에 `● 오늘` + 주 버튼 `코스 보기`. 시간별 진행·길찾기는 코스 상세에서 |
  | ⑤ 지난 코스만 | 예정 코스 없음 | ②와 같음 |
- ③④에만 할 일 한 줄: `장소 저장`(추출 탭) · `코스 만들기`(위저드)
- 그 아래 순서 고정(①은 지금 뜨는 장소만): **최근 저장한 곳**(가로 사진 줄, 일주일 안은 `n일 전`, 그 뒤는 `10월 12일`) → **이런 코스는 어때요?**(서버 추천 코스 가로 카드) → **지금 뜨는 장소**(2×2 사진 타일, 저장 여부 북마크 표시)
- 섹션 = `SectionCard` 하나(제목은 컨테이너 안). 바깥 여백 12, 컨테이너 사이 10, 안쪽 16
- 사진이 없는 장소는 카테고리 색 칸 + 아이콘(`PlaceImage`), 크기는 같다
- 제안을 닫은 시각은 기기 저장(`HomeNudgeStorage`). 코스를 만들면 같은 시각을 기록해 그때까지 저장한 곳은 제안에서 뺀다
- 데이터: 진행 중 코스 요약(`activeCoursesProvider`) · 통계 aggregate의 저장 수 · 최근 추출 N개 · 추천 코스 · 트렌딩. 추가 호출 없음. **각 섹션 독립 로딩/오류**, 데이터가 비면 섹션째 숨김, 실패하면 그 컨테이너 안에만 오류 + 다시 시도
- NEEDS BACKEND: '시각 이후 저장 수'(지금은 최근 추출 목록으로 앱이 셈), 최근 추출의 출처 계정 이름, 진행 중 코스 목록에 오늘 이후 코스가 포함되는지
- 시안 대비: 통계 3타일·최근 추출 카드 목록·내 코스 바로가기는 뺐다. 추천 코스 상세 화면은 디자인이 없어 스낵바
- 나중에 추가할 수 있는 것: 오늘 코스 시간별 타임라인(상세 1회 조회 + 시각 Provider + 순수 계산), 수동 '다음 장소로', 파티 진행 공유, 여러 날 코스

- UI (07 D26): 제목 "추출" → **링크 줄**(SectionCard 모양 · 링크 아이콘 칸 · 입력 · 값 있으면 X · 오른쪽 글자 버튼 `찾기`) → SectionCard "릴스에서 바로 저장하기"(아이콘 칸 + 한 줄 3개). 붙여넣기 버튼 · 하단 큰 버튼 없음(붙여넣기는 OS 길게 누르기).

### 11 추출 결과 검토 · `/extract/result`
- UI (07 D26): 헤더 "찾은 장소" → 링크 줄(#10과 같은 모양: 계정 이름을 받으면 `@계정 · 릴스`, 아니면 링크 · 오른쪽 `게시물 보기`) → SectionCard "찾은 장소 N"(`모두 선택/해제`): 행 = 사진 48 · 이름 · 카테고리 · 동네 · (고른 보관함 이름, 파랑) · `보관함` 글자 버튼 · 체크. 이미 저장한 곳은 흐리게 `저장됨`. 하단 `N곳 저장`.
- 찾는 중: 같은 자리에 링크 줄 + "장소를 찾고 있어요" 뼈대 행. 실패(비공개/장소 없음/링크 오류/분석 실패): 같은 자리에 아이콘 칸 + 이유 카드, 하단 `다른 링크 넣기`(분석 실패는 `다시 시도`).
- 공유 진입 시: 분석 로딩을 이 화면에서 보여주고 완료되면 목록 표시

### 12 보관함 고르기 · 바텀시트 (추출)

- 동작: 저장하지 않고 고른 값만 목록에 반영. 저장은 #11의 `N곳 저장` 한 번 — 같은 보관함 조합끼리 묶어 `savePlaces` (NEEDS BACKEND: 장소별 한 번 API, 일부 실패). 저장 뒤에는 결과에 남고 스낵바 `n곳을 저장했어요 · 보기`(1곳 → 장소 상세, 한 보관함 → 그 보관함, 그 밖 → 저장됨), 저장한 행은 `저장됨`, 남은 곳이 없으면 하단 `완료`(추출 탭으로).
- 장소 상세의 보관함 변경은 기존 시트(`showCollectionPickerSheet`) 그대로.

(2026-10-20 개편, 07 D21)
- 헤더: 제목 "저장됨" + 오른쪽 `지도` 버튼 하나(카테고리 탭이면 걸린 카테고리로 #18, 보관함 탭이면 #19). 저장 0곳이면 비활성. 떠 있는 `지도에서 보기`·섹션 `지도 보기`는 없앰
- 탭: 밑줄 탭 `[카테고리 | 내 보관함]` (`SegmentedTabs` underline 스타일)
- 본문은 홈과 같은 `SectionCard` 하나(바깥 여백 12) 안에 구분선 행
- **카테고리 탭(13)**
  - 필터 없음: 제목 `전체 n곳` + 오른쪽 `필터`. 카테고리 칩은 없음
