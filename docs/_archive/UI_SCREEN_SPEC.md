# UI_SCREEN_SPEC.md — Canonical UI 31개 화면 기준 Flutter 구현 명세

> 기준 패키지: `canonical_user_flow_ui_svgs_2026-10-03.zip` (플로우 7개, 모바일 화면 31개 + 전체 흐름도)
> 이 문서는 `DEVELOPMENT_DIRECTION.md`(제품/아키텍처 방향)의 **화면 단위 구현 기준**이다.
> **둘이 충돌하면 이 문서(실제 확정 UI)가 우선**한다. 단, 서버 계약(API)은 백엔드 명세가 최우선.

---

## 0. 개발 시 반드시 지킬 것

1. **구현 전에 `PREVIEWS/canonical_user_flow.jpg`(흐름도)와 `canonical_ui_31_screens.jpg`(31화면)를 먼저 확인**하고, 각 화면은 해당 SVG를 열어 상세 수치를 확인한다.
2. SVG는 **디자인 레퍼런스**다. SVG를 그대로 앱에 넣지 않고 Flutter Widget으로 재구현한다.
3. SVG 내부의 사진·지도는 **더미 이미지**다. 지도는 정지 이미지이므로 실제 지도 SDK로 대체한다 (아래 §3).
4. 하단 탭/아이콘 일부는 SVG에서 텍스트 글리프(`↝ ⌂ ⌗ ▱ ○`)로 그려진 곳이 있다. **실제 아이콘(Material Symbols 등)으로 구현**한다.
5. 서버 데이터(카테고리, 보관함, 코스, 파티, 통계)는 **하드코딩 금지**. 프리뷰의 문구/숫자는 예시다.

## 1. 전체 흐름 (요약)

```
[AUTH] 소셜 로그인 → 약관 → 프로필 → 가입 완료 → 홈      (예외: 계정 충돌 / 소셜 인증 오류)

홈 ─┬─ 추출 탭 ─ 링크 입력 → 추출 결과 검토 → 보관함 선택 → (저장됨 / 장소 상세)
    ├─ 저장됨 탭 ─ [카테고리 | 내 보관함] ─ 보관함 상세 / 빈 보관함 / 새 보관함
    │                └─ "지도에서 보기" → 카테고리 지도 / 보관함 지도·목록 → 장소 상세
    ├─ 코스 탭 ─ 빈 상태 / 목록(내 코스 | 모임·파티)
    │            └─ 코스 만들기 1/4 → 2/4 → 3/4(함께|혼자) → [초대 모달 / 장소 더 추가] → 4/4 AI 추천 → 완료 → 상세·관리
    └─ 마이 탭 ─ 프로필 · 취향 · 설정

장소 상세 ─ "보관함 변경" / "코스 만들기"
초대 링크 → 초대 수락 → 파티 코스
```

- 하단 탭 5개: **홈 · 코스 · 저장됨 · 추출 · 마이** (순서 유지). 활성 탭은 **현재 라우트 기준**으로 표시한다.
- 중간의 "어떤 기준으로 볼까요?" 화면은 **제거됨**. 저장됨의 현재 탭(카테고리/내 보관함) 기준으로 바로 지도 진입.

## 3. 지도 구현 메모

- SVG 지도는 이미지. 실제 구현은 지도 SDK 필요. 화면의 `지도 © NAVER` 표기 → **네이버 지도(flutter_naver_map 등)**로 보임. **지도 SDK 확정 여부를 먼저 확인할 것** (구글맵으로 바꾸면 크레딧/스타일이 달라짐).
- 핀: 번호 핀(파랑, 코스 순서), 선택 핀(강조), **AI 추천 핀(주황 ✦)**, 내 위치 점, 현재 위치 버튼.
- 바텀시트 + 지도 조합이 다수(16, 17, 22, 27, 28). **드래그 가능한 시트**(핸들 포함)로 공통화.
- 저장됨 지도는 "지도 이동 시 자동 검색" 칩과 "지도를 움직이면 이 지역의 저장 장소가 갱신돼요" 안내가 있으므로 **viewport 기반 조회 + debounce** 전제.
- 코스 경로선은 직선이 아니라 도로를 따르는 형태로 그려져 있음 → 서버/경로 API가 제공하는 polyline 사용 (제공 여부 확인).

## 7. 확인이 필요한 항목 (디자인/명세에 없음 → 임의 결정 금지, 질문 또는 제안 후 진행)
