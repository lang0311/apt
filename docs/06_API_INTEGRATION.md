# 06. 백엔드 연동 가이드

> 백엔드/AI는 **제공받는다.** 이 문서는 "앱이 서버에 무엇을 필요로 하는가"를 정리해 **API 명세를 받을 때/요청할 때 체크리스트**로 쓰기 위한 것이다.
> 엔드포인트, 필드명, enum은 **여기서 정하지 않는다.** (아래 예시 표기는 설명용)

> **백엔드 기준 (07 D12, 2026-10-25):** 팀 레포에 **실제로 구현된 서버 API**(GitHub 최신 `origin/main`의 `api.py`·`src/`, 로컬 clone은 `apt` 옆 `team/`)가 기준이다. API 작업 전 `git fetch`로 새 커밋을 확인하고 바뀐 API는 보고한다.
> `docs/API/API 정리.xlsx`는 서버와 작성자가 다른 초안(응답 형식 없음)이라 **서버에 없는 기능의 방향 참고로만** 쓴다. 둘이 다르면 서버를 따른다.

## 1. 연동 원칙

1. **실제 구현된 서버 코드가 Source of Truth**(그다음 엑셀 명세는 참고). 없는 필드/상태값을 추측해 구현하지 않는다.
2. 명세가 없는 기능은 `Repository Interface` + `Mock Repository`로 분리하고 `NEEDS BACKEND`로 기록한다. Widget 안에 mock JSON 금지.
3. `DTO → mapper → Domain Model → UI`. 서버 응답 구조가 바뀌어도 mapper만 수정하면 되게 한다.
4. 서버 데이터(카테고리, 취향 키워드, 보관함, 코스, 통계)는 **UI에 하드코딩하지 않는다.**
5. 서버 명세와 docs가 충돌하면 임의 선택 없이 **충돌 지점을 명시하고 제안**한다.
6. 외부 API 키(소셜, 네이버 지도, 길찾기 등)는 **앱에 비밀키를 넣지 않는다.** 클라이언트용 키만 사용하고 비밀 호출은 서버 경유.

## 4. 파티·취향 관련 — 서버 확인 결과 (2026-11-13)

- 파티원 취향 종합은 **서버가 한다.** 코스 응답의 `taste_profile`(`keywords`의 `shared_by` = 그 취향을 가진 파티원 수, `group_size`)과 `group_blend`(파티원별로 잘 맞는 장소 이름 `per_user[].strong_match_places`, 장소별 `selection_steps[].kind` = `shared` · `personal` · `complementary`)로 온다. 앱은 비율 없이 단어 한 줄과 장소별 펼치기만 보여 준다(07 D46).
- "내 저장 장소와 취향을 추천에 반영" 체크 값은 서버에 없다. 파티에 들어오면 그 사람의 저장 기록이 파티 추천에 쓰인다(참여 = 반영). 저장 기록이 없는 파티원은 `insufficient_history`로 표시되고 반영되지 않는다.
- 파티원에게 공개되는 정보: 파티원 이름 · id(`GET /parties/{party}`), 코스 결과에 합산된 취향 키워드와 파티원별로 잘 맞은 장소 이름.
- 저장 장소 기반 취향 자동 분석은 서버가 항상 계산한다. on/off 플래그는 없다.
- 파티 코스 편집 권한: 파티원이면 누구나 수정한다. 장소마다 만든 사람이 기록되지 않아 남이 넣은 장소도 뺄 수 있다. 동시 수정은 코스 `revision`으로 막는다 — 다른 사람이 먼저 저장했으면 409 `다른 참여자가 코스를 수정했습니다. 새로 불러와 주세요.`
- 초대 링크는 파티장만 만들 수 있다(파티원 403, 07 D43). 파티 이름 수정 · 나가기 · 삭제 API는 없다.

## 5. 공통 응답 처리

| 항목 | 앱 처리 |
|------|---------|
| 인증 만료(401) | 토큰 갱신 시도 → 실패 시 로그인으로 이동, 보류 중 공유 URL/초대 토큰 보존 |
| 권한/없음(403/404) | 도메인별 안내 화면 또는 토스트 (초대 만료 등) |
| 서버 오류(5xx)/네트워크 | 재시도 가능한 ErrorState, 스낵바 |
| 검증 오류(400/422) | 필드 인라인 오류 매핑 (닉네임, 보관함 이름, 이메일 형식 등) |
| 타임아웃 | 추출/추천은 긴 타임아웃 + 취소·재시도 UX |
| 페이지네이션 | cursor 제공 시 cursor, 아니면 page/size (명세 기준) |

## 6. Mock 전략

```
FeatureRepository (interface)
 ├── ApiFeatureRepository   ← 명세 수령 후
 └── MockFeatureRepository  ← 개발 초기, 프리뷰 화면과 동일한 샘플 데이터
```
- Mock 데이터는 `test/fixtures` 또는 `lib/dev/mock/`에 모으고 프리뷰 SVG의 문구(성수동 데이트 등)를 재사용해 시안 대비 확인을 쉽게 한다.
- `환경 플래그`로 Mock/실서버 전환 (예: `--dart-define=USE_MOCK=true`).
- Mock이 반드시 지켜야 할 것: **로딩 지연, 빈 응답, 오류 응답**을 흉내낼 수 있어야 한다 (상태 UI 검증용).

## 7. 백엔드에 요청할 목록 (요약 체크리스트)

2026-11-13 정리: 팀 서버가 실제로 구현되어 예전의 일반 항목(OpenAPI · 인증 방식 · 추천 API · 파티 API · 개발 서버)은 서버 코드와 §0 · §3 · §4로 답이 나왔다. 지금 남은 요청만 둔다. 서버를 고치는 일은 팀이 하고, 앱은 `NEEDS BACKEND` 주석과 Mock으로 대신하거나 준비 중으로 둔다.

### 서버 모드에서 사용자가 막히는 것 (먼저 요청)

- [ ] ★ **저장(확정)한 코스도 수정** — 확정한 코스의 순서 변경 · 빼기(`POST /mobile/courses/{id}`, `DELETE /courses/{id}/places`)와 다시 추천(`/replace`, `publish`)이 409다. `revision` 충돌 검사는 두고 확정 여부 검사만 빼고, 수정 뒤에도 `confirmed`를 유지해 달라. 새로 들어온 장소를 확정 때처럼 `course_confirmed`로 저장 목록에 넣을지도 정해 달라. 반영되면 앱 서버 모드 `canEdit`을 연다(07 §3).
- [ ] **같은 코스에 장소 추가 API** — `/mobile/courses`는 기존 장소의 순서 · 빼기만 받는다. 저장한 코스에 파티원이 장소를 넣으려면 같은 코스 id에 추가하는 방법이 필요하다(선택 토큰 목록을 받는 필드 등).
- [ ] 릴스 링크 장소 추출(엑셀 초안 `POST /api/v1/places/share-link`) — 앱의 주 진입 경로인데 서버에 없어 서버 모드는 준비 중
- [ ] 보관함 API(만들기 · 목록 · 상세, 장소와 다대다) — 서버 모드의 `보관함` 버튼이 준비 중(07 D32)
- [ ] 코스 삭제 · 코스 공유 — 코스 상세 ⋯ 메뉴가 준비 중
- [ ] 파티 이름 수정 · 나가기 · 목록에서 숨기기 · 삭제, 앱 푸시 알림
- [ ] 프로필 수정 · 사진 업로드 · 약관 동의 기록 · 취향 직접 설정 · 홈 추천 코스 · 지금 뜨는 장소(트렌딩) — 서버에 없어 Mock 유지

### 있으면 좋은 값 (앱이 대신 처리하거나 숨기는 중)

- [ ] `taste_profile.group_blend`에 장소 `key` — 지금은 이름으로만 와서 같은 이름의 장소를 구분하지 못한다. 편집 뒤에도 추천 당시 값이 남는 것도 공유한다(07 D46).
- [ ] `/mobile/summary`를 `action_type`(직접 저장 · 코스 확정)별로 — 지금 요약은 코스 확정으로 들어온 AI 추천 장소까지 세어, 저장됨은 앱이 `/me` 목록으로 직접 센다(07 D44).
- [ ] 장소 상세의 평점 · 영업 상태 · 사진, 지도 검색 결과의 대표 사진 · 짧은 소개 — 지금은 이름 · 주소 · 업종 · 위치만 와서 카드 이미지를 업종 아이콘으로 대신한다(07 D32).
- [ ] 장소 사이 이동 시간과 도로를 따르는 경로선 — 지금은 직선거리(`route_type: straight_line`)뿐
- [ ] 코스 목록 summary에 파티원 이름 — 지금은 파티 API를 따로 부른다
- [ ] 저장 목록의 정렬 · 페이지와 근처 저장 장소 API(`/places/nearby` 초안) — 지금은 `/me` 전체를 받아 앱이 거리 · 필터를 처리한다
- [ ] 추천 한도 초과를 구분하는 오류 코드 — 지금은 job 오류 문장에 `한도`가 들어 있을 뿐이다
- [ ] 초대 링크의 정식 도메인과 앱 링크(설치된 앱으로 바로 열기)
