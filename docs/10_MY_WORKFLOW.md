# 10. 내 작업 방식

> **개인 레포(`lang0311/apt`) 작업 규칙**이다. 팀원은 따를 필요가 없고, 이 문서는 팀 레포 `mobile/`에 반영하지 않는다(`.gitattributes` export-ignore).
> Claude는 이 파일이 있으면 **매 세션 작업 전에 읽는다.** 커밋·키·팀 레포 반영은 `09`.
>
> 기준일: 2026-10-25

## 1. 화면·흐름을 바꿀 때: 시안 먼저

- 순서: 지금 화면 캡처 → **시안(HTML 아티팩트)** → 사용자 확정 → Flutter 구현 → 에뮬레이터 확인 → 문서(03·04·05·07)·개발 일지 → 커밋
- 시안이 확정되기 전에는 코드·docs·커밋을 고치지 않는다. "적용해"라는 말도 **시안에 반영하라**는 뜻으로 읽는다.
- 디자인 작업은 **요청 하나마다** 디자인 skill(`ui-ux-pro-max`, `frontend-design`, 필요 시 `design:design-critique`·`design:ux-copy`)을 먼저 부르고, 어떤 근거로 정했는지 답변에 한두 줄 밝힌다. 세션 앞에서 한 번 불렀다고 생략하지 않는다.
- 시안은 게시 전에 Edge headless로 **캡처해서 직접 보고** 어색한 문구·떠 있는 줄·말투 불일치·화면 간 모양 차이를 고친 뒤 게시한다.
- 시안 페이지 구성: **확정된 화면만** 흐름 순서대로 깔끔하게, 미확정은 질문마다 **옵션 A/B를 화면으로 나란히** 두고 권장안 표시. 캡션은 한 줄, 보조 설명은 뺀다.
- 문구: AI스러운 감성 문구·장식을 넣지 않는다. 짧은 사실 서술(해요체), 애매하면 상용 앱(토스·카카오맵·네이버지도 등) 표현을 참고한다.
- 피드백은 **요청한 강도만큼만** 반영한다 ("약간 분리"는 약하게).

## 2. 시안 없이 해도 되는 경우

| 시안 없이 바로 | 시안 먼저 |
|---|---|
| 버그 수정 (의도한 모양으로 되돌리기) | 배치·순서·흐름 변경 |
| **확정된 시안을 그대로** 구현 | 새 요소(버튼·카드·섹션) 추가·삭제 |
| 오타, 문구의 단어 하나 | 문구 문장을 새로 쓰거나 톤 변경 |
| 화면 모양이 같은 리팩터·토큰 정리 | 색·간격·크기를 눈에 띄게 바꿀 때 |
| 문서·도구·설정 | 상태 화면(빈·오류·로딩) 새로 만들기 |

애매하면 물어본다.

## 3. 완료 기준

- 모든 커밋: `flutter analyze` 경고 0, `flutter test` 통과
- 화면·흐름 변경: **Pixel_6_Pro** 에뮬레이터에서 직접 확인 + 관련 통합 테스트(A–J) 통과
- 레이아웃을 바꾼 경우: 360 / 390 / 430 폭 확인
- 못 한 확인은 "확인 안 함: ○○"으로 보고한다. 했다고 쓰지 않는다.

## 4. 개발 일지

- **1단계 = 기능 묶음 하나** (예: "마이 개편", "추출 개편", "규칙 정리").
- 작은 수정은 따로 단계를 만들지 않고 **바로 다음 단계의 '기타'** 에 모아 적는다. 기능 묶음 없이 작은 수정만 며칠 쌓이면 "정리" 단계 하나로 묶는다.
- 방법: `tools/devlog/entries.js` 맨 아래에 항목 추가 → `cd tools/devlog && npm run build` → `docs/08_DEV_LOG.docx`를 같은 커밋에 포함. 이미 있는 단계의 문제 상태가 바뀌면 그 항목도 고친다.
- 키·Secret 값은 적지 않는다(관리 위치만). 일지는 팀 레포에 올리지 않는다.

## 5. 마무리 · 결정 대기

- 사용자 결정 대기는 두 곳에만 둔다.
  - **앱 기획·디자인 결정** → `07` §3 "사용자 결정 대기" 표
  - **개인 작업 결정**(규칙 정리, 팀 레포 운영, 테스트 계획 등) → Claude 메모리 `next-session-todo`
- 기능 묶음 하나를 마칠 때 메모리에서 끝난 항목을 정리한다. 해결된 건 "해결됨"에 한 줄로, 긴 기록은 메모리 `archive/`로 옮긴다.
- 팀 레포 반영은 작업 끝에 **제안만** 한다(실행은 요청 받은 뒤, `09`).
