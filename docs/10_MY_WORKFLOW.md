> 기준일: 2026-10-25

## 1. 화면·흐름을 바꿀 때: 시안 먼저

- 순서: 지금 화면 캡처 → **시안(HTML 아티팩트)** → 사용자 확정 → Flutter 구현 → 에뮬레이터 확인 → 문서(03·04·05·07)·개발 일지 → 커밋
- 시안이 확정되기 전에는 코드·docs·커밋을 고치지 않는다. "적용해"라는 말도 **시안에 반영하라**는 뜻으로 읽는다.
- 디자인 작업은 **요청 하나마다** 디자인 skill(`ui-ux-pro-max`, `frontend-design`, 필요 시 `design:design-critique`·`design:ux-copy`)을 먼저 부르고, 어떤 근거로 정했는지 답변에 한두 줄 밝힌다. 세션 앞에서 한 번 불렀다고 생략하지 않는다.
- 시안은 게시 전에 Edge headless로 **캡처해서 직접 보고** 어색한 문구·떠 있는 줄·말투 불일치·화면 간 모양 차이를 고친 뒤 게시한다.
- 시안 페이지 구성: **확정된 화면만** 흐름 순서대로 깔끔하게, 미확정은 질문마다 **옵션 A/B를 화면으로 나란히** 두고 권장안 표시. 캡션은 한 줄, 보조 설명은 뺀다.
- 문구: AI스러운 감성 문구·장식을 넣지 않는다. 짧은 사실 서술(해요체), 애매하면 상용 앱(토스·카카오맵·네이버지도 등) 표현을 참고한다. ✦·주황은 AI 추천 표시로만 쓴다(CLAUDE.md, 07 D17).
- 피드백은 **요청한 강도만큼만** 반영한다 ("약간 분리"는 약하게).

## 2. 시안 없이 해도 되는 경우

| 시안 없이 바로 | 시안 먼저 |
|---|---|
| 버그 수정 (의도한 모양으로 되돌리기) | 배치·순서·흐름 변경 |
| **확정된 시안을 그대로** 구현 | 새 요소(버튼·카드·섹션) 추가·삭제 |
| 오타, 문구의 단어 하나 | 문구 문장을 새로 쓰거나 톤 변경 |
| 화면 모양이 같은 리팩터·토큰 정리 | 색·간격·크기를 눈에 띄게 바꿀 때 |
| 문서·도구·설정 | 상태 화면(빈·오류·로딩) 새로 만들기 |

애매하면 물어본다.

## 4. 개발 일지

- **1단계 = 기능 묶음 하나** (예: "마이 개편", "추출 개편", "규칙 정리").
- 작은 수정은 따로 단계를 만들지 않고 **바로 다음 단계의 '기타'** 에 모아 적는다. 기능 묶음 없이 작은 수정만 며칠 쌓이면 "정리" 단계 하나로 묶는다.
- 방법: `tools/devlog/entries.js` 맨 아래에 항목 추가 → `cd tools/devlog && npm run build` → `docs/08_DEV_LOG.docx`를 같은 커밋에 포함. 이미 있는 단계의 문제 상태가 바뀌면 그 항목도 고친다.
- 키·Secret 값은 적지 않는다(관리 위치만). 일지는 팀 레포에 올리지 않는다.

  - **앱 기획·디자인 결정** → `07` §3 "사용자 결정 대기" 표

- 팀 레포 반영은 작업 끝에 **제안만** 한다(실행은 요청 받은 뒤, `09`).

## 6. 도구 (개인 레포)

- 팀 서버 켜기: VS Code `Ctrl+Shift+B` → `tools/start_server.ps1`(`apt` 옆 `team/`의 `.venv`로 `127.0.0.1:8000`, 이미 켜져 있으면 다시 켜지 않음). 그다음 실행 및 디버그에서 `apt (서버 연결, …)`
- 개발 일지: `tools/devlog/entries.js` → `cd tools/devlog && npm run build` (§4)
- 시안 캡처: Edge headless `--screenshot` (§1). 앱 화면 캡처는 Pixel_6_Pro + `adb exec-out screencap`, 여러 화면은 임시 통합 테스트로 이동하며 캡처하고 테스트 파일은 커밋하지 않는다
- Figma(개인 파일 `1HIjbBK2F8H6RQUwUCqTO9`, 페이지 `initial` · `revised` · `revised 2`): `revised 2`에 2026-10-31 최신 화면 54개 — 흐름별 섹션 9개(로그인 · 가입 / 홈 / 저장됨 · 장소 상세 / 보관함 · 저장 지도 / 추출 / 코스 만들기 / 코스 상세 · 편집 / 초대 / 마이), 화살표는 실제로 출발한 화면에서(옆 화면은 가로 화살표, 앞 화면에서 갈라지면 위로 꺾인 선), 섹션 첫 화면엔 '들어오는 길'. 10-31부터 화면마다 **누르는 곳**을 분홍 외곽선 + 번호로 표시(화면 위 레이어 `핫스팟 · a01`), 화면 아래 `동작 · a01` 표에 이 화면에서 할 수 있는 모든 동작(종류 · 컴포넌트 · 결과)을 적고, 화살표 · 갈래 이름 앞에 같은 번호(①②)를 붙였다. 결과 색: 파랑 = 같은 섹션 화면, 검정 [n] = 다른 섹션, 회색 = 같은 화면 안 변화 · 알림. 동작은 코드의 onTap · 라우트 기준(54개 화면 181개). 한 줄 = 텍스트 레이어 하나(구간별 굵기 · 크기 · 색). 화면은 SVG(에뮬레이터에서 Flutter가 그린 요소의 위치 · 색 · 글자를 그대로 옮김: 상자는 사각형 · 원 레이어, 글자는 텍스트 레이어, 아이콘은 Material 아이콘 벡터, 지도 · 사진 · 상태바는 캡처에서 잘라 넣음). 10-31부터 화면 안 요소는 **컴포넌트 인스턴스**: 섹션 `화면에서 뽑은 컴포넌트`에 Flutter 위젯 클래스별 컴포넌트 세트 64개(이름 = 클래스 이름, 설명에 `lib/` 경로, 변형 = 위젯 값(variant · selected · disabled 등) + 모양이 다르면 `형태=n`) + 아이콘 49개. 모양 · 배치가 같은 것끼리만 한 변형으로 묶고 글자 · 색 · 사진은 인스턴스에서 바꿨다(Figma 인스턴스는 안쪽 레이어 위치를 못 바꿈). 화면 54개 인스턴스 1,292개, 에뮬레이터 캡처와 평균 차이 약 1.8/255. 그 아래(앞서 손으로 만든) 변수 `APT 토큰` · `AppButton` · `SectionCard` · `BottomCta`는 따로 남아 있다. 다시 만들 때 쓴 임시 도구(화면 요소 뽑기 테스트(위젯 클래스 기록 포함) + SVG 변환기 + Figma 정리 · 컴포넌트화 스크립트)는 커밋하지 않았다
