# Flutter PC 실행과 현재 Python 서버 연결

`run.cmd`는 이제 Flutter 앱을 웹으로 빌드하고 Python 서버를 실행합니다. 기존 웹 화면 소스는 삭제하지 않았으며 `start-servers.ps1`로 별도 실행할 수 있습니다.

- PC 앱: http://127.0.0.1:8000/mobile-app/
- 서버: http://127.0.0.1:8000/docs
- Flutter SDK: `%USERPROFILE%\develop\flutter` (3.47.7, Dart 3.13.5로 검증)
- 수동 빌드: `flutter build web --base-href /mobile-app/ --dart-define=APT_BACKEND=true --dart-define=USE_MOCK=false --dart-define=API_BASE_URL=http://127.0.0.1:8000`

## 기존 앱과 달라진 점

`APT_BACKEND=true`에서만 실제 Python 서버 어댑터를 사용합니다. 기존 mock 모드는 그대로 유지합니다. 공통 Repository 인터페이스와 기존 위저드/화면/디자인을 재사용합니다.

| 기능 | 연결 상태 |
|---|---|
| 인증 | 기존 서버의 아이디·비밀번호 가입/로그인, HttpOnly 쿠키 세션(웹은 브라우저, Android·iOS는 앱이 보안 저장소에 직접 보관). 로그인 화면은 아이디·비밀번호 + 간편 로그인 아이콘(카카오·Google), 아이디 가입은 약관 → 계정 정보 → 가입 완료. 소셜로 로그인하면 서버 대신 앱 안의 Mock 데이터를 씀(07 D28) |
| 장소 검색·저장 | 추출 탭의 `지도에서 검색하기`(저장됨이 비었을 때 `장소 찾기`로도 들어감). 지도 핀 + 카드 목록, `현재 지도에서 검색하기`(지도 가운데 주변), 서명 토큰으로 개인 DB 저장. 카드의 `보관함` 버튼은 서버에 보관함이 없어 준비 중 안내(07 D32) |
| 저장 장소·카테고리 | `/me` 및 서버 집계 `/mobile/summary` 사용 |
| 코스 생성 | 저장 장소 1~6곳을 필수 포함. 총 방문 수는 선택 수+3, 최대 6곳 |
| 추천 | 기존 Sonar→지도·방문 적합성 검증→DeepSeek 코스 구성. 비동기 작업 폴링 |
| 코스 수정 | 서버의 장소 키·리비전으로 기존 장소 삭제/재정렬. 새 장소 주입 차단 |
| 재추천 | 이전 추천 코스의 제외 장소를 서버에 반영한 뒤 추천 장소 교체 |
| 코스 완성 | 이름·날짜·순서를 저장하고 서버에서 확정. 확정 후 읽기 전용 |
| 파티 | 코스 만들기 동행 단계에서 파티 생성, 초대 링크, 참여, 파티 기록 기반 추천, 기존 파티 고르기(`GET /me`의 parties), 저장 후 코스 링크로 파티원에게 알리기 |
| 지도 | 웹은 OpenStreetMap 타일을 flutter_map으로 표시, Android·iOS는 네이버 지도(07 D29). 화면 폭 560 제한은 웹에서만(07 D30) |

현재 서버의 실제 API가 명세의 원본입니다. `docs/API/API 정리.xlsx`의 향후 API 초안과 다르게 `/auth`, `/me`, `/jobs`, `/courses`, `/parties` 경로에 맞춰 연결했습니다. 이 차이는 미래 API를 구현한 것으로 간주하지 않습니다.

## 미연동 기능과 제한

- 약관 동의 기록, 프로필 편집, 보관함 CRUD, SNS 링크 추출, 홈 트렌딩, 수동 취향 설정은 현재 Python 서버에 대응 기능이 없어 미연동입니다. 모의 결과로 대신하지 않고 준비 중으로 둡니다.
- 소셜 로그인은 서버가 지원할 때까지 앱 안의 Mock 데이터로 동작합니다(아이디 로그인 = 서버 데이터, 소셜 로그인 = Mock 데이터. 화면에 따로 표시하지 않음).
- 지도 검색 결과에는 사진·소개가 없어 카드 이미지를 업종 아이콘으로 대신합니다.
- 추천의 사용자 취향 집계는 기존 백엔드에서 자동 수행합니다. 앱의 분위기 선택은 현재 서버 입력에 없어서 옵션을 노출하지 않습니다.
- 경로는 직선 연결이며 실제 도보 경로·예약·영업시간·이동시간을 계산하지 않습니다.
- PC 웹은 공개 OSM 타일 서비스 사용 조건을 따릅니다. 상용 트래픽에는 정식 타일 제공업체를 구성해야 합니다. 웹 지도를 네이버 지도로 표시하지 않습니다.
- 개발자 모드를 켜거나 Windows 네이티브 빌드 도구를 설치하지 않고 웹으로 실행합니다. Android 에뮬레이터 실행은 아래 절을 보세요. 실기기·iOS는 아직 검증하지 않았습니다.
- 기존 서버가 이미 실행 중인데 `/mobile-app/`가 404이면 이전 서버를 종료하고 다시 `run.cmd`를 실행하세요.
- 웹 주소의 호스트는 `127.0.0.1`로 통일합니다. `localhost`와 섞으면 세션 쿠키가 공유되지 않습니다.

## Android 에뮬레이터로 실행

서버는 PC에서 띄우고(`team` 폴더에서 `uvicorn api:app --host 127.0.0.1 --port 8000`), 앱은 `mobile`(개인 레포는 `apt`) 폴더에서 실행합니다. 에뮬레이터에서 PC는 `10.0.2.2`로 보입니다.

```
flutter run --dart-define=APT_BACKEND=true --dart-define=USE_MOCK=false --dart-define=API_BASE_URL=http://10.0.2.2:8000 --dart-define-from-file=config/dev.json
```

- VS Code에서는 실행 및 디버그의 `apt (서버 연결, 에뮬레이터)`를 고릅니다. 웹은 `apt (서버 연결, 웹)`(포트 5173 — 서버 CORS가 `127.0.0.1:5173`만 허용).
- `config/dev.json`은 지도·소셜 로그인 키 파일로 커밋하지 않습니다(만드는 법은 02 §12). 없으면 그 옵션을 빼고 실행해도 서버 연결은 됩니다(지도는 미리보기, 소셜 로그인은 Mock SDK).
- 초대 링크는 `API_BASE_URL` 기준 웹 주소(`…/mobile-app/#/invites/코드`)로 만들어져, 에뮬레이터에서 만든 링크는 에뮬레이터에서만 열립니다.

## 인증·데이터 보호

OpenRouter·지도 REST 비밀키는 Python `.env`에서만 읽습니다. Flutter 빌드에는 서버 주소와 공개 지도 타일 주소만 포함합니다. 코스 편집 API는 사용자/파티 권한과 리비전을 검사하며 기존 지도 검증 장소의 키만 허용합니다. 로그인 없이 사용자 기록을 조회할 수 없습니다.
